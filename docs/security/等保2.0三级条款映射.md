# 等保 2.0 三级 · 安全通用要求 ↔ 平台能力映射

> 面向等级保护 2.0（GB/T 22239-2019）第三级「安全计算环境 / 安全通信网络 / 安全管理中心」相关技术要求，
> 逐条对照平台已落地的安全能力与配置加固项。本表随安全能力演进持续更新。

## 一、身份鉴别（8.1.4.1）

| 等保三级要求 | 平台能力 | 落点 |
| --- | --- | --- |
| a) 用户身份标识唯一、鉴别信息复杂度、定期更换 | 用户名唯一约束；密码复杂度策略（min-length + 大小写/数字/特殊字符组合，可后台调）；密码有效期与历史密码防重用 | `SecurityPolicyService`、`sys_password_log`、`sys_param` 策略 |
| b) 登录失败处理、超时退出 | 登录失败锁定（连续失败锁账户）；会话超时；图形验证码 | `LoginLockService`、`CaptchaService`、Sa-Token 会话 |
| c) 远程管理防鉴别信息网络窃听 | **登录/改密/注册密码 SM2 非对称加密传输**（前端 sm-crypto 公钥加密、后端 Hutool 私钥解密）；密码 BCrypt 加盐哈希存储 | `Sm2Util`、`GmCryptoConfig`、`AuthController.decodePassword`、`PasswordEncoder` |
| d) 两种或以上组合的鉴别技术 | 双因子登录（密码 + 二次验证码），可开关 | `TwoFactorService` |

## 二、访问控制（8.1.4.2）

| 等保三级要求 | 平台能力 | 落点 |
| --- | --- | --- |
| a) 为登录用户分配账户和权限 | RBAC：用户-角色-菜单/按钮权限码 | `sys_user_role`、`sys_role_menu`、`@SaCheckPermission` |
| b) 重命名/删除默认账户、修改默认口令 | 超管码/租户号集中常量（无散落魔法值）；默认口令策略化 | `RoleConstants`、`TenantConstants` |
| c) 及时删除/停用多余、过期账户 | 用户/角色启用停用、逻辑删除 | `sys_user.status`、`is_deleted` |
| d) 授权主体配置访问控制策略、最小权限 | 权限码 fail-closed 兜底（写接口无注解自动派生 `sys:<域>:<动作>`，仅授权放行）；数据权限（部门/自定义范围）；多租户字段隔离 + 独立数据源隔离 | `PermissionGuardInterceptor`、`@DataScope`、`TenantContext`、`TenantDataSourceRegistry` |
| e) 主客体粒度访问控制 | 列级/字段级脱敏与读写门控（角色感知） | `@ColumnMask`、`RoleAwareMaskProcessor` |
| f) 敏感标记与强制访问控制 | 字段脱敏三级（不可见/脱敏/明文）+ 审计恒脱敏 | 字段权限引擎 |

## 三、安全审计（8.1.4.3）

| 等保三级要求 | 平台能力 | 落点 |
| --- | --- | --- |
| a) 覆盖每个用户，重要行为与安全事件审计 | **写接口自动留痕切面**（无需手工注解，POST/PUT/DELETE）；操作日志 + 数据变更审计 | `AutoAuditAspect`、`AuditService`、`sys_oper_log`、`sys_data_audit` |
| b) 记录日期时间、用户、事件类型、是否成功等 | 记录 operator/ip/请求方法/URI/参数/状态/耗时/错误 | `SysOperLog` |
| c) 审计记录保护，防未预期删除、修改、覆盖 | **哈希链（SM3）+ SM2 签名防篡改 + 验签闭环**：任一记录改/删/插即链断裂或签名失配，验签精确定位；验签管理员门控 + 有界防 DoS | `OperationLogService.verify`、`GET /system/oper-log/verify` |
| d) 审计进程保护 | 异步独立落库，密码脱敏，超长截断 | `AuditMask`、`@Async` |

## 四、数据完整性与保密性（8.1.4.8 / 8.1.4.9）

| 等保三级要求 | 平台能力 | 落点 |
| --- | --- | --- |
| 鉴别数据、重要业务数据传输完整性 | 开放接口 **HMAC 签名**（method/URI/query/时间戳/nonce/body 哈希），篡改即失配 | `OpenApiSignService` |
| 传输保密性 | 密码 SM2 传输；接口国密 SM4-CBC（随机 IV，消除 ECB 确定性） | `Sm2Util`、`ApiCryptoService` |
| 存储保密性 | 敏感字段 SM4 加密存储；密钥环境变量外部注入 | `Sm4Util`、`@ColumnEncrypt`、`${ENV:}` 注入 |
| 数据备份恢复 | 逻辑删除 + 独立数据源；哈希链可核验历史 | — |

## 五、入侵防范（8.1.4.5）

| 等保三级要求 | 平台能力 | 落点 |
| --- | --- | --- |
| 遵循最小安装、关闭非必要服务 | 精简模块；开放接口按 scope 授权 | `OpenScope` |
| 提供数据有效性检验（防注入/XSS） | **全局 XSS 净化**（参数转义 + 富文本白名单过滤 + 前端 DOMPurify 统一）；**SQL 注入防护**（orderBy/列名白名单、参数化、schema 名标识符校验）；**JDBC-RCE 防护**（连接串高危参数/内嵌库拦截 + URL 解码防绕过） | `XssFilter`/`XssCleaner`/`v-safe-html`、`SqlSafeUtil`、`JdbcUrlValidator` |

| 能够发现可能的已知漏洞并及时修补 | 依赖国密/BouncyCastle 等安全库；连接串攻击面封禁 | — |

## 配置加固指南（部署前必做）

1. **密钥外部注入**：`MUGSUN_SM2_PRIVATE_KEY`/`MUGSUN_SM2_PUBLIC_KEY`/`MUGSUN_SM4_KEY`/`MUGSUN_API_KEY` 经环境变量或配置中心注入固定值（勿用生成默认，否则重启后历史密文不可解）。
2. **国密开关**：生产 `MUGSUN_GM_ENABLED=true`（登录 SM2 强制、摘要 SM3）。
3. **令牌**：生产环境单独配置 `sa-token`，不要用仓库里的本机默认口令。
4. **验证码/短信明文回显**：生产 `mugsun.captcha.show-code=false`、`mugsun.sms.show-code=false`。
5. **开放接口签名**：`mugsun.open-api.sign-required=true`，客户端须携 X-Timestamp/X-Nonce/X-Sign。
6. **审计验签**：定期调用 `GET /system/oper-log/verify`（管理员）核验审计链完整性。
7. **数据源连接串**：仅经受校验的 `JdbcUrlValidator` 入池；禁用内嵌库连接串。
