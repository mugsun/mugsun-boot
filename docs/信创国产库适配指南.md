# 信创国产库适配指南

本平台主库为 PostgreSQL，通过 MyBatis-Flex 的方言自动探测能力支持多数据库部署。本文说明国产信创库（金仓 KingbaseES、达梦 DM 等）的适配方案、部署步骤与边界。

## 1. 兼容族划分

平台将各数据库按 SQL 语法归并为三大兼容族，差异收敛在 `com.mugsun.boot.gen.SqlDialect`：

| 兼容族 | 代表库 | 信创归属 | 主键/整型 | 时间戳 | 大文本 | 变长字符 |
| --- | --- | --- | --- | --- | --- | --- |
| **PG 系** | PostgreSQL、**金仓 KingbaseES**、**openGauss**、**华为 GaussDB**、瀚高 HighGo、海量 VastBase、Greenplum | ✅ | `BIGINT` / `INT4` | `TIMESTAMP` | `TEXT` | `VARCHAR(255)` |
| **Oracle 系** | Oracle、**达梦 DM**、OceanBase(Oracle 模式) | ✅ | `NUMBER(19)` / `NUMBER(10)` | `TIMESTAMP` | `CLOB` | `VARCHAR2(255)` |
| **MySQL 系** | MySQL、MariaDB、OceanBase(MySQL 模式)、GoldenDB | — | `BIGINT` / `INT` | `DATETIME` | `TEXT` | `VARCHAR(255)` |

目标库由 Flex `DbTypeUtil.getDbType(dataSource)` 探测其 `DbType` 后自动归族（`SqlDialect.of(DbType)`），未识别库回退 PG 系，保证不因新库型中断建表。

## 2. 方言自动适配机制

- **常规 CRUD / 分页 / 雪花主键**：由 MyBatis-Flex 按数据源 `DbType` 自动选择 `IDialect`（分页 LIMIT/OFFSET/ROWNUM、标识符引用、批量语法均自适配）。主数据源在启动时探测；租户独立数据源经 `FlexDataSource.addDataSource(key, ds)` 注册时按各自 URL 探测，互不影响。
- **代码生成器动态建表**（`DdlService`）：建表/同步/改列的 DDL 类型按 `SqlDialect` 出型，已去除单一 PG 硬编码；物理列内省对 Oracle 系（达梦）未加引号标识符大写存储做了大小写双探测。

## 3. 金仓 KingbaseES 部署（PG 系，推荐路径）

金仓为 PG 线协议 + 语法兼容，可近乎无缝复用平台 PG 部署：

```bash
mvn -Pkingbase clean package -DskipTests   # 引入金仓 JDBC 驱动
```

```yaml
spring:
  datasource:
    url: jdbc:kingbase8://<host>:54321/mugsun
    username: <user>
    password: <pwd>
  flyway:
    locations: classpath:db/migration      # 复用 PG 迁移脚本（金仓 PG 兼容）
```

- 语法上可复用 `db/migration`（`INT4`/`TEXT`/部分索引/`ON CONFLICT`/`RETURNING` 等）。**联调注意**：社区金仓 JDBC 上报 `DatabaseMajorVersion=8` 时，社区 Flyway PostgreSQL 插件会抛 `FlywayDbUpgradeRequiredException`——可用手工 `ksql -f`（或厂商支持的 Flyway 扩展）灌库，业务 SQL 须 **schema 限定**（见 §6）。
- 平台内多数运行时 SQL 为 PG 语法，金仓兼容；裸 SQL 未带 schema 时可能命中 `SYS_CATALOG.sys_*`，须 `mugsun.db.default-schema` + 限定表名。

## 4. 达梦 DM 部署（Oracle 系，需专项适配）

达梦属 Oracle 系，DDL 类型经 `SqlDialect.ORACLE` 自动出型；但平台存在少量 PG 特有运行时 SQL（§5），需专项方言适配后方可完整运行：

```bash
mvn -Pdameng clean package -DskipTests     # 引入达梦 JDBC 驱动
```

```yaml
spring:
  datasource:
    url: jdbc:dm://<host>:5236?schema=MUGSUN
    username: <user>
    password: <pwd>
  flyway:
    locations: classpath:db/migration-dm   # 与 PG 的 db/migration 并列，避免递归扫描版本冲突
```

**Flyway 多厂商目录纪律**：PG 迁移脚本（`INT4`/`TEXT`/部分索引/`RETURNING`）不适用于达梦，须在 `db/migration-dm` 下维护同版本号的 Oracle 语法脚本，并引入 `flyway-database-oracle`。勿把达梦 `V*__*.sql` 放进 `db/migration/dm/`（Flyway 会递归扫描导致与 PG 同版本冲突）；该路径仅放重定向 README。平台默认只交付 PG 脚本，达梦脚本随专项适配落地。

### 4.1 多数据源 / 多厂商：别人怎么做（结论）

| 做法 | 谁在用 | 要点 |
| --- | --- | --- |
| **每数据源一套独立 Flyway** | Baeldung / Spring 社区惯例 | `spring.flyway.enabled=false`，再为 primary / secondary 各 `Flyway.configure().dataSource(...).locations("classpath:db/migration/<ds>").migrate()`；**禁止**把两套脚本放在同一递归根下，否则会互相污染 |
| **主库自动 + 副库手动** | mugsun 现状 | 主库 `spring.flyway` → `db/migration`；埋点 `TrackFlywayConfig` → `db/track/migration`（刻意不注册第二个 `Flyway` bean，避免自动装配注入冲突） |
| **分厂商全量 SQL，不用 Flyway** | **BladeX / BladeX-Boot** | 仓库内 **无 Flyway**；`doc/sql/bladex/bladex.{mysql,postgres,kingbase,dameng,oracle,...}.all.create.sql` + upgrade 手工导入。金仓脚本实质是 PG 导出口径 |
| **社区金仓 + 社区 Flyway-PG** | 本联调已证伪 | 社区镜像缺真 `pg_catalog`，仅伪装 major/minor **不够**；正确路径是：与 PG **同脚本语义**，执行通道用 `ksql`/厂商工具 + baseline；官方金仓（catalog 更全）再评估开 `spring.flyway` |

**推荐模型（mugsun）**：

```
主库真 PG     → spring.flyway          → db/migration
埋点库        → TrackFlywayConfig      → db/track/migration   （独立 history）
主库达梦      → 专用 Flyway（Oracle 插件）→ db/migration-dm
主库金仓社区  → 关 spring.flyway；ksql 灌同语义脚本 + flyway_schema_history baseline（可选）
```

「每个数据源不同 Flyway」**是对的**——解决的是 **多库实例隔离**；「每个厂商不同目录」解决的是 **SQL 方言**。二者正交，不要合成一套硬跑。

## 5. PG 特有运行时 SQL 清单（达梦适配待办）

以下为达梦（Oracle 系）需改写的 PG 特有 SQL，金仓（PG 系）不受影响：

| 位置 | PG 特性 | 达梦改写方向 |
| --- | --- | --- |
| `TableColumnController` / `WorkbenchController` | `INSERT ... ON CONFLICT ... DO UPDATE` + `now()` | `MERGE INTO` + `SYSTIMESTAMP` |
| `SysNoticeController` | 同上 + `RETURNING (xmax = 0)`（PG 系统列判首次插入） | `MERGE` + 应用层判定是否新增 |
| `AbstractSerialNumberGenerator`（流水号核心） | `INSERT ... ON CONFLICT ... DO UPDATE` + `excluded.*` + `greatest()` + `now()` | `MERGE INTO` + `GREATEST` + `SYSTIMESTAMP` |
| `FlowService` 等原生 `INSERT` | `now()` | `SYSTIMESTAMP` |
| `TenantDataSourceRegistry`（SCHEMA 模式多租户隔离） | `SET search_path TO ?` + `SELECT 1 FROM information_schema.schemata` | `ALTER SESSION SET CURRENT_SCHEMA = ?` + 查 `ALL_USERS`/`DBA_OBJECTS` 系统视图 |
| `MugsunDataScopeDialect` | 固定 PG 双引号 + PG LIMIT/OFFSET | 按 `DbType` 选达梦分页（Oracle 模式 `OFFSET ... FETCH`） |
| `DdlService` 建表语句形状 | `DROP TABLE IF EXISTS` + 列定义 `NOT NULL DEFAULT`（列类型已按族出型） | `DROP TABLE`（Oracle 无 `IF EXISTS`）+ 列定义 `DEFAULT ... NOT NULL` 顺序 |
| `db/migration/*.sql` | `INT4`/`TEXT`/部分索引/`RETURNING` | Oracle 语法脚本（见 §4；目录 `db/migration-dm`，**0.1 基线 `V1__baseline_0_1.sql` 已转换**；联调达梦灌该单文件即可） |

> 常规 Entity CRUD、分页、逻辑删除、雪花主键、字段加解密均由 Flex 方言层自适配，无需改写。
> `DdlService` 的建表**列类型**已按方言族出型（Oracle 系落 `NUMBER`/`VARCHAR2`/`CLOB`）；§5 所列运行时语句形状已按 `SqlDialect`/`RuntimeSql` 分支（PG 路径保持 `ON CONFLICT`/`now()`）。

## 6. 运行时实测边界

- **代码层已就绪**：多方言建表（`SqlDialect`）、金仓/达梦 JDBC 驱动 profile（`-Pkingbase`/`-Pdameng`，驱动版本见 `pom.xml` 属性）、方言自动探测、达梦标识符大小写处理、§5 运行时 SQL 方言分支（`RuntimeSql`/`DbDialects`）、`db/migration-dm` **0.1 基线单脚本**（`scripts/pg_to_dm.py` 自 PG 转换；含 GIS 要素表的达梦占位逻辑）。
- **驱动获取**：金仓 `kingbase8`、达梦 `DmJdbcDriver18` 为厂商私有构件，不在 Maven 中央仓库；需从厂商获取 jar 并 `mvn install` 到本地仓库或部署私服（Nexus），`-Pkingbase`/`-Pdameng` 方可解析。
- **金仓/openGauss（PG 系）**：现有 PG 语法与迁移脚本兼容，切换数据源即可运行。冒烟脚本见 `scripts/smoke-pg-compat.sh`；`SqlDialectTest` 覆盖金仓/openGauss→POSTGRES、达梦→ORACLE 归族及 MERGE/SYSTIMESTAMP 片段。
- **达梦（Oracle 系）**：DDL 类型与 §5 运行时 SQL 已按族分支；`db/migration-dm` 为 **0.1 基线 `V1__baseline_0_1.sql`**。社区 Flyway **不认** `DM DBMS 8.1`，灌库走 JDBC 逐语句（lab 关 `spring.flyway`）。关键字列须与 Flex DmDialect 大写引号对齐（`"TYPE"`/`"DOMAIN"`，禁止小写 `"type"`）。

## 7. GIS / PostGIS 降级（2026-08-30）

本地开发交付物以 `mugsun-boot/docker-compose.yml` 为准：镜像由 `docker/postgres/Dockerfile` 构建，`FROM postgis/postgis:16-3.4` 再装 `postgresql-16-pgvector`（钉 `platform: linux/amd64`）。不要退回官方 `postgres` 镜像再手工 `apt install`。建库脚本会用 `ON_ERROR_STOP` 装 `postgis` 与 `vector`——镜像换错则容器起不来。

| 能力 | PostgreSQL + PostGIS | 达梦 / 金仓 / 无扩展的 PG |
| --- | --- | --- |
| 要素加速表 `gis_feature` | 0.1 基线建 `geometry(Geometry,4326)` + GiST | DM 脚本跳过 DO 块，表不建；金仓若未装扩展同样不建 |
| 空间查询（bbox / 半径 / 相交 / 包含 / 最近邻 / 缓冲） | 下沉 SQL，响应 `engine=postgis` | 读 `gis_layer.data_json` 在 Java 侧算，`engine=java`；万级图层 p95 抖动明显 |
| 矢量瓦片 MVT | `ST_AsMVT` | **不可用**（接口明确 400，前端回落整层 GeoJSON） |
| 如何发现降级 | `/system/gis/spatial/status` 的 `postgis`/`mvt`；工作台右上角标签；启动后首枪 WARN 日志 | 同上 |

达梦 / 金仓上 GIS **不静默失败**：查询与分析仍可用，只是慢且无瓦片。运维切国产库前应看工作台标签与 `spatial/status`，不要只看接口 200。
